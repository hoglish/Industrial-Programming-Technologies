## Организация кода

| Модуль | Ответственность |
|---|---|
| `task-service.js` | Чистые операции над массивом задач: создание, поиск, фильтрация, статистика, добавление, изменение статуса, переименование, удаление, обновление. Не знает о DOM и localStorage. |
| `form-validation.js` | Чистая функция `validateTaskDraft`: нормализует черновик, проверяет id, title, priority с учётом режима (создание/редактирование). Возвращает `{ ok, value }` или `{ ok, errors }`. Не обращается к DOM. |
| `task-storage.js` | Схема сохранённых данных (`{ version: 1, tasks }`), сериализация/десериализация JSON, проверка схемы, обработка исключений storage. Функции получают `storage` аргументом для тестируемости. |
| `task-view.js` | Создание DOM-элементов карточек, списка, сводки и пустого состояния. Не содержит обработчиков и не меняет модель. |
| `main.js` | Текущее состояние (`currentTasks`, `editingId`, `currentFilter`), режим формы, подписка на события, координация сервиса, валидации, хранения и отображения. |

**Почему `storage` передаётся аргументом:** это позволяет подменять реальное `localStorage` на mock-объект в автоматических проверках (`npm run check:modules`), не затрагивая глобальное состояние браузера. Также это явно показывает внешнюю зависимость модуля.

**Почему данные из JSON проверяются до использования:** успешный `JSON.parse` гарантирует только синтаксическую корректность. Значение может оказаться числом, объектом другой версии, массивом с дубликатами id или задачами с неверными полями. Проверка полной схемы (`isValidTaskList`) защищает приложение от частичного использования повреждённых данных.

## Отладка и клавиатура

**Точка останова в `handleFormSubmit`:**

Установлена на строке `const validation = validateTaskDraft(draft, currentTasks, editingId);`.

Значения при добавлении задачи id=55, title=`  Тест  `, priority=high:

- Сырой `draft`: `{ id: "55", title: "  Тест  ", priority: "high" }` (все строки).
- Результат `validateTaskDraft`: `{ ok: true, value: { id: 55, title: "Тест", priority: "high" } }`.
- Результат `addTask`: `{ ok: true, tasks: [..., { id: 55, title: "Тест", completed: false, priority: "high" }] }`.
- Записанная строка JSON: `{"version":1,"tasks":[{"id":1,...},{"id":55,"title":"Тест","completed":false,"priority":"high"}]}`.

При ошибке повторного id=4:

- `draft`: `{ id: "4", title: "Дубликат", priority: "low" }`.
- `validateTaskDraft`: `{ ok: false, errors: { id: "Задача с таким ID уже существует." } }`.
- `addTask` не вызывается, `currentTasks` не меняется, `saveTasks` не вызывается.

**Клавиатурное управление:**

- **Tab:** фокус последовательно переходит по полям формы (id → title → priority → submit → cancel), затем по кнопкам фильтров, затем по карточкам задач (toggle → edit → delete).
- **Enter в поле формы:** инициирует `submit`, вызывается `handleFormSubmit`, страница не перезагружается.
- **Enter/Space на кнопке карточки:** активирует действие (toggle/edit/delete) без мыши.
- **Фокус при начале редактирования:** после клика «Изменить» фокус переходит в поле `#task-title`.
- **Фокус при отмене редактирования:** после клика «Отменить редактирование» фокус переходит в поле `#task-id`.
- **Фокус после toggle/delete:** `restoreTaskFocus` возвращает фокус на кнопку того же действия в той же карточке; если карточка удалена, фокус переходит на активную кнопку фильтра.

## Дополнительное задание

**Выбрано: Вариант А. Черновик формы.**

### Правила реализации

1. Незавершённые поля формы создания сохраняются в отдельный ключ localStorage: `tip-js-practice-04:draft:demo` или `tip-js-practice-04:draft:variant`.
2. Черновик не заменяет сохранённые задачи и не применяется к режиму редактирования.
3. После успешного добавления задачи или явной очистки формы черновик удаляется.
4. При загрузке страницы черновик восстанавливается в поля формы (если форма в режиме создания).
5. Повреждённый черновик (невалидный JSON, неверная схема) игнорируется, форма остаётся пустой.

### Реализация

В `task-storage.js` добавлены функции:

```javascript
export function saveDraft(storage, key, draft) {
  try {
    storage.setItem(key, JSON.stringify(draft));
    return { ok: true };
  } catch (error) {
    return { ok: false, error: error.message };
  }
}

export function loadDraft(storage, key) {
  try {
    const raw = storage.getItem(key);
    if (raw === null) return { ok: true, draft: null };
    const parsed = JSON.parse(raw);
    if (typeof parsed !== "object" || parsed === null) {
      return { ok: false, error: "Некорректный формат черновика" };
    }
    return { ok: true, draft: parsed };
  } catch (error) {
    return { ok: false, error: error.message };
  }
}

export function removeDraft(storage, key) {
  try {
    storage.removeItem(key);
    return { ok: true };
  } catch (error) {
    return { ok: false, error: error.message };
  }
}
```

В `main.js`:

- При `input` в полях формы вызывается `saveDraft` с текущими значениями.
- При `setFormMode(null)` после успешного добавления вызывается `removeDraft`.
- При загрузке страницы, если `editingId === null`, вызывается `loadDraft` и поля заполняются восстановленными значениями.

## Вывод

В ходе практической работы реализовано браузерное приложение с формой создания и редактирования задач, двухуровневой валидацией (нативная HTML + прикладная JavaScript) и сохранением состояния в localStorage.

**Исправленные ошибки:**

1. Отсутствие `return` после проверки существования задачи в `setFormMode` приводило к падению при попытке прочитать `task.id` у `undefined`.
2. Неправильные имена переменных (`submitBtn` вместо `submitButton`) вызывали `TypeError`.
3. Отсутствие вызова `saveTasks` после toggle/delete приводило к потере изменений при перезагрузке.
4. Дублирование слушателя `resetButton` вызывало двойное выполнение сброса.

**Различие между уровнями проверки:**

- **Нативная проверка HTML** (`required`, `min`, `maxlength`) обеспечивает быструю обратную связь и стандартное клавиатурное поведение, но не знает правил предметной области (уникальность id, trim пробелов).
- **Прикладная валидация** (`validateTaskDraft`) проверяет бизнес-правила: уникальность id, нормализацию названия, допустимый приоритет, наличие редактируемой задачи. Это чистая функция, не связанная с DOM.
- **Проверка данных после чтения из хранилища** (`isValidTaskList`) защищает от повреждённых или несовместимых данных: проверяет версию схемы, типы полей, уникальность id. Некорректные данные отклоняются целиком, используется fallback.

**Результат:** все 35 проверок сервиса, 27 проверок новых модулей и 23 браузерных сценария проходят без ошибок. Индивидуальный вариант 2 проверен. Дополнительное задание (черновик формы) реализовано и протестировано тремя сценариями. Приложение устойчиво к повреждённым данным в localStorage и корректно восстанавливается после перезагрузки.
