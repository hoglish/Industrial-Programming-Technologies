## 4. Модель данных и функции
Модель задачи включает поля: `id` (число), `title` (строка), `completed` (boolean), `priority` (string).
*   `data.js`: хранит исходные наборы данных (`demoTasks` и `variantTasks`).
*   `task-service.js`: содержит 9 чистых функций для работы с данными (создание, поиск, фильтрация, изменение, удаление). Не зависит от DOM и глобальных переменных.
*   `main.js`: демонстрационный сценарий, который импортирует данные и сервис, выполняет последовательность действий и выводит результаты.

**Почему id не равен индексу:** `id` — это уникальный идентификатор записи, который сохраняется даже при удалении других задач или изменении порядка массива. Индекс — это временная позиция в массиве, которая меняется при любых операциях добавления или удаления.

**Почему getTaskStats возвращает число, а не строку с процентом:** Функция сервиса должна возвращать «чистые» данные для дальнейших вычислений. Округление и форматирование (добавление знака `%`) выполняются на уровне представления (в `main.js` через `toFixed(1)`), чтобы отделить логику расчета от логики вывода.

**Какие объекты копируются при изменении задачи:** При операциях `setTaskCompleted` и `renameTask` создается новый массив задач. Внутри этого массива неизмененные задачи используются по ссылке из старого массива, а измененная задача заменяется на новый объект-копию с обновленным полем. Это гарантирует иммутабельность входного массива.

## 9. Вывод
В отличие от ПР1, где все вычисления происходили в одном файле с примитивными типами, в ПР2 логика разделена на модули. Данные теперь хранятся в массивах объектов, а операции над ними инкапсулированы в функциях сервиса. Ключевым моментом стало освоение иммутабельности: вместо изменения существующих объектов создаются новые копии массивов и объектов, что предотвращает побочные эффекты. Также была исправлена ошибка в эксперименте со стрелочными функциями (пропущенный `return`).
